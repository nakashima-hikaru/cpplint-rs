## 2026-05-13 - [Fast NOLINT string finding over Regex]
**Learning:** `NOLINT_RE` regex execution inside `parse_nolint_suppressions` was evaluated on every line with a comment. Replacing a simple regex parsing with `find("NOLINT")` and manual byte-boundary emulation (`is_alphanumeric()`) provides around a ~4.5x micro-benchmark speedup without breaking functionality. This showcases that on ultra-hot paths for a linter, specialized string scans are notably faster than the `regex` crate engines for simple keyword capture operations.
**Action:** Always prefer manual `find` and boundary byte checking over `Regex` for high-frequency string/keyword lookups in standard, highly repetitive text parsing functions within this codebase.
